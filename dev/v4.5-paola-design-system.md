# v4.5 Paola: LearnTerms design system on shadcn-svelte

Design upgrade only. Move from DaisyUI 5 to shadcn-svelte (bits-ui + Tailwind 4) without losing the site's personality. Tailwind stays. Nothing changes behaviour or the backend.

## Where the personality lives (keep all of this)

- **Pills everywhere:** `rounded-full` buttons and inputs, `btn-circle` icon buttons, the split previous/next pill.
- **Role-based button variants** (quiz dock rule): solid = primary action, outline = state toggle, dash = preference, ghost = quiet utility. Plus `soft`. The user disliked everything being soft.
- **Semantic tones** on buttons and badges: primary, secondary, accent, info, success, warning, error, plus the lemon **highlighter** and **ember** streak orange. ClassCard's 12 palettes map onto these tones.
- **Surfaces:** `border-base-300` hairlines on `base-100`/`base-200`, `bg-graph-paper`, `panel-graph`, `graph-stage`.
- **Type:** system sans body, `font-display` (Space Grotesk) on page `h1`s only, Geist Mono for data (kbd, IDs, page refs).
- **Bespoke pieces:** `BrandLogo` (animated), `ColorMark`, `ProgressRing`, soft navigator dots, `AnswerOptions` (swipe to eliminate), Quiz Dock, `Sheet` drag.

## Approach

1. **Tokens first, visuals unchanged.** Port DaisyUI's stock light and dark oklch values into shadcn's variables (`--background`, `--foreground`, `--card`, `--muted`, `--border`, `--primary`, …) and add the extra tones shadcn lacks (`--success`, `--warning`, `--info`, `--accent`, `--secondary`, each with `-foreground`, plus `--highlighter`, `--ember`). During migration, keep the DaisyUI names working (`--color-base-100` → `--background`, `--color-base-300` → `--border`, `--color-base-content` → `--foreground`) so the ~1,300 `base-content` uses and the `<style>` blocks don't need to change at once.
2. **Dark mode keeps `data-theme`:** `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *))`. No mode-watcher. Clerk theme and `theme-color` meta stay as they are.
3. **DaisyUI and shadcn coexist.** shadcn components are Tailwind utilities in `$lib/components/ui/*`, so they don't collide with `btn`/`card`. Migrate one surface at a time. Remove the DaisyUI plugin last.
4. **Restyle the shadcn defaults to LearnTerms.** Generated components are owned code: give Button pill radius and the full variant × tone matrix, Card `rounded-2xl`, Dialog `rounded-2xl`, Input pill. Don't ship stock shadcn looks.
5. Keep `lucide-svelte` (configure shadcn's icon import) and Bun only (`bunx shadcn-svelte@latest`).

## Design order

### Tier 0: foundation (before any component)

- `components.json`, `cn()` util, bits-ui, tailwind-variants, tailwind-merge, tw-animate-css
- Token sheet: colours (light/dark), the DaisyUI aliases, radius scale (`--radius` around 1rem; pill and 2xl as named steps), shadows, focus ring
- Type tokens: sans, `font-display`, `font-mono`
- A `/dev/design` page (dev-only) that renders every primitive in both themes, so each step can be compared with the current site

### Tier 1: the most-used primitives (~80% of DaisyUI uses)

1. **Button**: variants `solid | soft | outline | dash | ghost | link` × tones `neutral | primary | secondary | accent | info | success | warning | error | highlighter | ember`; sizes `xs | sm | md | lg`; shapes `pill | circle | square`. The dock's `segment-start/end` stays a prop. This is the hardest and most important one: 119 files, and the dock customizer stores these variants by name.
2. **Badge**: same variant × tone matrix as Button, sizes `xs | sm | md`.
3. **Dialog + Sheet**: shadcn Dialog on bits-ui, then rebuild `Sheet.svelte` on it with the **same props**, so its 9 callers and the drag handle work unchanged. Add `AlertDialog` for `DeleteConfirmationModal`.
4. **Form controls**: Input, Textarea, Select (native-select first; bits Select only where it's custom), Label, Field (label + error). Pill inputs; 2xl textareas; error state.
5. **Alert**: inline error, warning and success (soft by default).
6. **Spinner + Skeleton**.
7. **Card**: `rounded-2xl`, hairline border, with a `graph` surface variant (`panel-graph`) for public pages.

### Tier 2: interactive and data

8. **DropdownMenu**: replaces focus-based `dropdown` + `menu` (dock overflow, class list, question list, tag manager).
9. **Tabs**: segmented pill style (`tabs-box` look).
10. **Checkbox, Switch, RadioGroup, Slider**: Checkbox must fit `AnswerOptions` (primary, xs/sm).
11. **Progress**: bar with tones; `ProgressRing` stays bespoke but uses the tokens.
12. **Kbd**: Geist Mono, xs/sm.
13. **Tooltip**: replaces `data-tip`; decide whether to upgrade the ~90 `title=` tooltips.
14. **Table**: admin progress, library, changelog.
15. **ToggleGroup / ButtonGroup**: replaces `join` segmented controls.

### Tier 3: long tail

Avatar, Separator, Collapsible, Popover + Command (rebuild `SearchablePicker`), Sonner or a restyled `Toast.svelte`, Breadcrumb, stat cells. Replace `navbar`, `hero`, `timeline`, `footer`, `mockup`, `chat` with plain Tailwind.

### Stays bespoke (restyle on tokens, not shadcn)

`AnswerOptions`, Quiz Dock and `DockButton`, `ProgressRing`, `ColorMark`, `BrandLogo`, `ClassCard`, `ModuleRow`, navigator dots, exam-findings boxes, graph-paper utilities.

## Migration order by surface (after Tier 1 lands)

1. Study flow: quiz page, dock, sheets (what students see most)
2. `/classes`, class and module pages
3. Practice tests (new, runner, results; heaviest single files)
4. Settings, badges, cohort
5. Admin catalog modals, then question editor, progress and Question Studio
6. Public pages and docs
7. Remove the DaisyUI plugin and the alias tokens; run `bun run verify`

## Status (2026-10-18)

Decisions: keep all eight DaisyUI role colours; adopt svelte-sonner; tune to the brand sheet now; new tooltip. Space Grotesk was too loud as the interface font on quiz pages, so the UI uses the neutral system sans and Space Grotesk stays on page titles and the wordmark (`font-display`).

Landed:

- shadcn-svelte 1.7 (Vega preset, bits-ui) in `$lib/components/ui`, restyled to the brand: pill controls, 24px cards and dialogs, brand role colours, `--line` hairlines.
- Tokens in `src/app.css`: shadcn names plus the role colours with `-foreground` (text on the solid) and `-ink` (text on the page), `highlighter` and `ember`. A bridge keeps the DaisyUI classes rendering on the same tokens until the plugin is removed. DaisyUI's `--border` is a width, so the border colour token is `--line`.
- Codemod: `base-content/100/200/300` and `*-content` renamed across the app (2,699 replacements in 167 files).
- `Button`, `Badge`, `Alert`, `Progress` share `tone.ts` (variant × tone). `Tip` is the new tooltip (ink pill + `Kbd`). `toastStore` is a facade over svelte-sonner. `Sheet.svelte` is rebuilt on bits-ui Dialog with the same props.
- `/design-system` shows every primitive in both themes.
- Quiz Dock: `dockStyles.ts` renders commands through `buttonVariants`; desktop dock buttons show the new tooltip with their shortcut.
- Surface migrations follow `dev/v4.5-paola-migration-guide.md`.

Remaining: remove the `daisyui` plugin and the bridge block once no DaisyUI classes are left; decide whether native `title=` tooltips move to `Tip`.
